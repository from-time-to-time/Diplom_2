# Diplom 2

## О проекте
Репозиторий содержит автотесты для проверки API веб-сервиса «StellarBurgers».
Тесты написаны на **Python + Pytest** с использованием requests для HTTP-запросов и **Allure** для отчетности.

---

## Структура репозитория

```text
.
├── allure_results/                   # результаты для Allure
│
├── src/
│   ├── __init__.py
│   └── stellar_burger_api.py                     # базовый URL, методы
│
├── tests/
│   ├── conftest.py                   # фикстуры Pytest
│   ├── test_create_order.py          # тесты создания заказа
│   ├── test_get_user_orders.py       # тесты получения списка заказов пользователя
│   ├── test_user_change.py           # тесты изменения данных пользователя
│   ├── test_user_login.py            # тесты авторизации пользователя
│   └── test_user_registration.py     # тесты регистрации пользователя
│
├── venv/                             # виртуальное окружение (локально)
├── README.md
└── requirements.txt                  # зависимости проекта

```

## Фикстуры (tests/conftest.py)
**register_new_user**</br>
Регистрирует нового пользователя через POST /api/auth/register на https://stellarburgers.nomoreparties.site и, если ответ успешный (200), возвращает данные пользователя, а также access- и refresh-токены.</br>
**cleanup_user**</br>
Очищает созданного пользователя по завршении теста.</br>
**user_payload**</br>
Генерирует рандомные данные для регистрации пользователя.</br>
**valid_ingredients**</br>
Возвращает список с валидными хэшами ингредиентов.</br>
**invalid_ingredients**</br>
Возвращает список с невалидными хэшами ингредиентов.</br>

## Описание тестов

### `tests/test_create_order.py` — **TestCreateOrder**
| Тест-кейс                                                | Что проверяет                                                                                                                          |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Создание заказа с авторизацией и валидными ингредиентами | Успешное создание заказа (код **200**, `success: true`), наличие ключа `order` и непустого списка `order.ingredients`.                 |
| Создание заказа без авторизации                          | Корректную обработку неавторизованного запроса — код **401** и `success: false` (тест помечен `xfail` из-за известной проблемы в API). |
| Создание заказа без ингредиентов                         | Валидацию обязательного поля `ingredients` — код **400**, `success: false`.                                                            |
| Создание заказа с невалидными ингредиентами              | Корректную обработку некорректных id ингредиентов — код **500**, `success: false` (с приложением тела ответа в Allure при ошибке).     |
| Корректность тела ответа                                 | Для всех успешных сценариев: `success == expected_success`, структура ответа содержит ожидаемые поля.                                  |

---

### `tests/test_get_user_orders.py` — **TestGetUserOrders**
| Тест-кейс                                     | Что проверяет                                                                                                            |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Получение заказов пользователя с авторизацией | Авторизацию по `access_token` и успешный ответ (код **200**, `success: true`) при пустой истории заказов.                |
| Создание заказа и повторное получение списка  | Что после POST на создание заказа список заказов больше **0**, заказ появляется в истории; код **200**, `success: true`. |
| Получение заказов без авторизации             | Корректную ошибку при отсутствии заголовка `Authorization` — код **401** и сообщение `"You should be authorised"`.       |

---

### `tests/test_user_change.py` — **TestChangeData**
| Тест-кейс                            | Что проверяет                                                                                                                                                   |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Изменение `email` с авторизацией     | Успешное изменение с токеном: код **200**, `success: true`, новое значение `user.email` в ответе.                                                               |
| Изменение `password` с авторизацией  | Код **200**, `success: true`. Повторный логин проходит **только** со вновь заданным паролем.                                                                    |
| Изменение `name` с авторизацией      | Код **200**, `success: true`, новое значение `user.name` в ответе.                                                                                              |
| Изменение `email` без авторизации    | Запрет на изменение без токена: код **401**, `success: false`, сообщение `"You should be authorised"`. Логин по новому email невозможен, по старому — возможен. |
| Изменение `password` без авторизации | Код **401**, `success: false`, сообщение `"You should be authorised"`. Логин с новым паролем невозможен, со старым — возможен.                                  |
| Изменение `name` без авторизации     | Код **401**, `success: false`, сообщение `"You should be authorised"`. Имя **не изменилось** (получаем актуальные данные и сравниваем со старым значением).     |

---

### `tests/test_user_login.py` — **TestLogin**
| Тест-кейс                                    | Что проверяет                                                                                                            |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Авторизация зарегистрированного пользователя | Успешный логин: код **200**, `success: true`, наличие в ответе `user.email`, `user.name`, `accessToken`, `refreshToken`. |
| Ошибка при неверном `email` или `password`   | Для искажённого значения одного из полей — код **401** и сообщение `"email or password are incorrect"`.                  |

---

### `tests/test_user_registration.py` — **TestUserRegistration**
| Тест-кейс                                                               | Что проверяет                                                                                                                                              |
| ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Создание нового пользователя                                            | Успешная регистрация: код **200**, `success: true`, совпадение `user.email` и `user.name` с отправленными данными, наличие `accessToken` и `refreshToken`. |
| Попытка регистрации уже существующего пользователя                      | Корректную ошибку дубликата — код **403**, сообщение `"User already exists"`.                                                                              |
| Создание без одного из обязательных полей (`email`, `password`, `name`) | Валидацию обязательных полей — код **403**, сообщение `"Email, password and name are required fields"`.                                                    |
